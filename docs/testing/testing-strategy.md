# Phase 10A — Testing strategy

Phase 10 introduces a complete quality-assurance programme across the
SGE modernisation. Phase 10A ships the test **foundations** that every
later subphase (10B – 10G) builds on. No business modules are added;
no existing test is weakened.

## Goals

1. Establish a single, durable test directory layout that coexists with
   the existing top-level `__tests__/`.
2. Provide shared factories and helpers so tests stop inlining
   fixtures.
3. Lock the API envelope contract (`apiSuccess` / `apiFailure`) behind
   typed assertions and a leak guard.
4. Codify the security regression baseline: IDOR filtering,
   authentication middleware, authorization matrix, file security, and
   cross-tenant storage keys.
5. Add migration-SQL validation and data-quality invariants that run
   without a live database.
6. Wire CI artefacts (JUnit XML, coverage report, test summary) so
   later subphases can produce nightly and release-quality reports.

## Non-goals for 10A

- No real-database integration tests (the sandbox has no live
  PostgreSQL). The test database helper (`tests/helpers/database.ts`)
  guards every test that would need one with `SGE_LIVE_DB=true`. 10B
  is the subphase that promotes these to real runs.
- No Playwright. 10D introduces the E2E framework.
- No axe-core. 10E introduces the accessibility harness.
- No k6 / Artillery. 10F introduces the load suite.
- No CI workflow changes (sandbox). The CI YAML will be updated in 10G.

## Test directory layout

```
tests/
  README.md
  unit/                       ← cross-cutting unit tests
  integration/                ← tests that exercise the Prisma adapter
  contracts/                  ← API envelope + Zod contract tests
  security/                   ← authn, authz, IDOR, SSRF regression
  e2e/                        ← Playwright (10D)
  accessibility/              ← axe + keyboard harness (10E)
  performance/                ← baselines + k6 scripts (10F)
  fixtures/                   ← shared factories
  helpers/                    ← shared helpers (contracts, auth, db)
  migrations/                 ← migration-SQL validation
```

Existing tests in `/__tests__/` are **not** moved. New tests live under
`tests/`. Both directories share the same vitest configuration.

## Test pyramid

```
                  /\
                 /  \           Few E2E (critical journeys only)
                /    \
               /------\        Moderate security + contract
              /        \
             /----------\      Many unit + factory-driven tests
```

Phase 10A only ships the bottom of the pyramid plus the contract and
security layers. E2E (10D), accessibility (10E), and load (10F) will
fill the top.

## Coverage policy

The vitest thresholds declared in `vitest.config.ts` are:

- lines: 60
- functions: 60
- statements: 60
- branches: 50

These match the existing baseline. Subphases 10B – 10G may raise them
incrementally for new code, but no existing test is weakened to make
the suite pass.

`pnpm test:coverage` enforces the thresholds. CI does not yet run
coverage (10G will add it).

## Test policy

- No test may depend on a real network call. Anything that touches the
  outside world must be replaced with a stub.
- No test may mutate a real database without `SGE_LIVE_DB=true`. Any
  test that requires the database must `it.skip(...)` when the flag is
  absent.
- A test that asserts on a private field is rejected at review.
- A test that depends on file ordering is rejected at review.
- A flaky test must be quarantined within one week. See
  `docs/testing/flaky-tests.md`.

## CI artefacts

- `pnpm test:coverage` produces `coverage/lcov.info`, `coverage/index.html`,
  and `coverage/coverage-summary.json`.
- `pnpm test:report` reads JUnit XML and the coverage summary, prints a
  short JSON report. The JUnit XML is generated by
  `pnpm vitest run --reporter=junit --outputFile.junit=reports/junit.xml`
  (see `scripts/test-report.mjs`). CI will upload these as artefacts in
  10G.
- The PR pipeline runs `pnpm test` (no coverage, fast). The nightly
  pipeline runs `pnpm test:coverage` and `pnpm test:report`. The
  release pipeline runs both plus the live-database integration suite.

## Quality gates

| ----------------- | ------------------------------ | ------- | --------------- |
| Lint              | `pnpm lint`                    | 10A     | yes             |

| Unit              | `pnpm test`                     | 10A     | yes             |
| Security regression | `pnpm test:regression`        | 10A     | yes             |
| Coverage          | `pnpm test:coverage`            | 10A     | warn (10B blocks) |
| Migration SQL     | `pnpm test` (no live DB)        | 10A     | yes             |
| E2E               | Playwright                       | 10D     | yes             |
| Accessibility    | axe                              | 10E     | yes (critical)   |
| Performance       | k6                               | 10F     | warn (10G blocks)|
| Live database    | `pnpm test:integration`         | 10B     | yes             |
| Release report    | `pnpm test:report`              | 10G     | yes             |
